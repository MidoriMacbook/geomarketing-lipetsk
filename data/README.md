# Начальные снимки OpenStreetMap

JSON в `snapshots/` содержат `fetched_at` (Unix UTC) и `data`.
Дома: `[широта, долгота, оценка жителей]`; конкуренты: `[широта, долгота]`.
Имя файла включает тип данных, район, координаты центра и радиус.

Елецкий и центр перенесены из ранее загруженного кэша проекта. Для этих двух
районов `fetched_at` — исходное время сохранения файла на 11 октября 2026 года,
а не время ревизии объектов в OSM. Университетский обновлён после исправления
координат района по [OSM relation 17717422](https://www.openstreetmap.org/relation/17717422).
Для него 11 октября 2026 года использована разовая выгрузка основного OSM API
`/api/0.6/map` по рамке центра с радиусом 1400 м (1000 м + запас для конкурентов),
поскольку Overpass возвращал 504/500. К выгрузке применены те же теги домов и
бизнесов и формулы оценки населения из `osm.py`. Центры контуров конкурентов —
центры их ограничивающих прямоугольников. Последующие обновления идут через Overpass.
Снимки служат стартовой копией, пользователь может обновить их через интерфейс.

Геоданные © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright),
[Open Database License 1.0](https://opendatacommons.org/licenses/odbl/1-0/).
Значения жителей рассчитаны проектом на основе тегов OSM и являются оценками.
Данные не включают персональную информацию о жителях.

При обновлении функций запас границы для конкурентов исправлен: не меньше
радиуса соответствующей категории (500 м для аптек и 450 м для салонов).
Снимки этих двух категорий заново получены 12 октября из выгрузок с запасом
500 м; имена включают `_halo500`/`_halo450`. Старые копии с запасом 400 м больше
не используются, чтобы не терять конкурентов у пограничных рекомендаций.

## Дополнительные категории (12 октября 2026)

Для продуктовых магазинов (shop=supermarket/convenience), пекарен (shop=bakery)
и салонов красоты (shop=hairdresser/beauty) добавлены отдельные снимки всех
трёх районов. Они получены из небольших XML-выгрузок основного OSM API 0.6.
Магазины и пекарни используют запас 400 м; для них в Университетском использована
сохранённая выгрузка от 11 октября. Салоны используют запас 450 м и обновлённые
выгрузки всех районов от 12 октября, как и аптеки с запасом 500 м. Дата в JSON
соответствует исходному файлу выгрузки.

Инструмент подготовки: `scripts/import_osm_competitors.py`. Например:

```bash
python scripts/import_osm_competitors.py --district center --business bakery --source center-source.osm --fetched-at UNIX_SECONDS
```

Инструмент проверяет корень OSM и покрытие `<bounds>` до записи, затем фильтрует
теги общего каталога `src/domain/businesses.py`, рамку и дубликаты. HTML-ошибка, неполная
выгрузка или неполная геометрия подходящего объекта отклоняются; прежний снимок
не перезаписывается. Успешная полная пустая выгрузка допустима.
Контуры используют центр ограничивающего прямоугольника. При неполных отношениях
импорт прекращается, чтобы не вычислять центр по обрывочной геометрии.
Сырая XML-выгрузка в репозиторий не входит. Пустой список означает, что объектов
с соответствующими тегами не найдено в полученной выгрузке; это не подтверждает
отсутствие реальных конкурентов. Полнота данных зависит от заполнения OSM.

## Расширение каталога (18 октября 2026)

Десять областей × десять категорий используют 110 отдельных снимков: десять
наборов домов и сто наборов конкурентов. Исходные18файлов сохранены без изменения.
Координаты новых жилых ориентиров и происхождение каждого нового снимка
зафиксированы в `catalog-provenance.json`: URL/OSM-объект, дата получения,
покрытие, SHA-256 исходной выгрузки и результирующего JSON. При разделении
большой рамки или дополнении отношений записываются все исходные запросы.

Новый офлайн-инструмент не загружает данные из сети:

```bash
python scripts/import_osm_area.py --district pobeda --source pobeda.osm --fetched-at UNIX_SECONDS
```

Без `--business` готовятся дома и все категории; повторяемый `--business KEY`
готовит только выбранных конкурентов, сохраняя прежние дома. Время передаётся
из записи реального получения HTTP-ответа. `mtime` не считается доказательством.
Покрытие конкурентов — 1000 + max(400,R) метров; фитнес требует1900м.
Все выбранные наборы проверяются до замены любого файла. Ошибки/remark,
повторяющиеся ID, неправильные координаты, недостаточное покрытие и неполная
геометрия подходящих объектов отклоняются. Ограничены размер XML, число объектов,
глубина отношений и суммарная работа раскрытия геометрии. Несвязанные отношения
маршрутов/административных границ не требуют полной геометрии.

Сырые выгрузки служат локальным доказательством импорта и не входят в runtime;
публикуются обработанные ODbL-данные и manifest с источниками и хешами.

## Происхождение новых записей (1 ноября 2026)

Числовые строки домов и конкурентов не изменились. Новые кэши и импортированные
снимки дополнительно содержат необязательный `provenance` версии 1:
`records` параллелен `data`, каждая запись содержит `osm_type`, `osm_id` и
`fetched_at`. Для домов записываются теги, площадь основания, правило оценки
(`flats`, `private_house`, `footprint_levels`), коэффициенты и округление.
`geometry_sha256` позволяет отметить точное совпадение полученной последовательности
координат; это не проверка полной топологии и не полигон административной границы.
Для неподписанных тестовых/старых источников ID остаётся неизвестным, а не выдумывается.

В городской выгрузке прежняя `schema: 1` дополнена необязательным полем
`provenance: {schema: 1, houses: ..., competitors: {...}}`; каждый вложенный набор
содержит такой же параллельный массив. Отсутствующий блок набора обозначается
`null`. Контрольная сумма учитывает метаданные. Старые выгрузки, снимки и браузерные
архивы читаются; переписывание исходных 110 снимков не выполнялось.

Новые загрузки сливают только повторы одного `osm_type + osm_id`; основание
`deduplication: osm_type_id`, число устранённых повторов исходной загрузки —
`duplicates_removed`. Противоречивые повторы одного ID отклоняются. Разные ID,
включая близкие заведения, сохраняются. Близкие точка и контур отмечаются в
`possible_node_way_pairs`, разные ID с точно одинаковой последовательностью
геометрии — в `same_geometry_groups`. Это кандидаты на проверку, не разрешение
удалить объект. Совпадение геометрии при другом порядке узлов может не обнаружиться.

Выборка новой ежедневной выгрузки сохраняет эту семантику, как и live-загрузка и
новые резервные снимки. Старый daily без ID сохраняет прежнее объединение по
округлённым координатам ради воспроизводимости старых расчётов. Его ограничения
сохраняются до получения новой выгрузки. В API передаётся только компактная сводка
`data_meta.*.provenance`, полные ID и признаки остаются в исходном наборе.
Даты наборов с происхождением берутся из исходных записей; сохранение или проверка
версии их не освежает. Время старых файлов остаётся прежним.

Оба импортёра требуют `--fetched-at` из подтверждённой записи получения; standalone
импортёр больше не выдаёт `mtime` исходного файла за дату загрузки. Перед запуском
нового сборщика в публикации следует развернуть сервер, понимающий optional
`provenance`. Сборщик не публикует файл сам: публикация выполняется отдельным скриптом.
Реально собранный 1 ноября новый файл занимает 10 752 787 байт (10,255 МиБ):
23 373 дома и 1 213 категорий конкурентов. Прежний предел 10 МиБ уже мал;
предел чтения увеличен до 32 МиБ и остаётся ограниченным.
