## Что должен делать сайт

Пользователь выбирает кофейню или аптеку и район Липецка либо область на карте. Сайт загружает жилые здания и конкурентов, оценивает население, рассчитывает взвешенные центры спроса и рейтинг возможных мест. На карте отображаются дома, конкуренты, центроиды, перспективные зоны и рекомендуемая точка. Результат сопровождается объяснением, источником, датой данных и предупреждением об их неполноте. Сайт должен открываться по публичной HTTPS-ссылке без установки Python у посетителей.

Рекомендация означает максимум выбранной математической модели при заданных данных и ограничениях. Она не гарантирует коммерческую успешность и наличие пригодного помещения.

## Текущая структура

- `app.py`: Flask, API `/api/calculate`, проверка области, демо-данные, взвешенный K-means и расчёт сетки 60 × 60.
- `osm.py`: Overpass API, выборка домов и конкурентов, приблизительная оценка населения, файловый кэш на семь дней.
- `static/index.html`: интерфейс, Leaflet, карта OSM, запрос к API, слои и вывод результата.
- `check.py`: диагностика внешних серверов и принудительное обновление данных. Это не автоматический тест: обновление может вернуть старый кэш, а скрипт засчитает загрузку успешной.
- `requirements.txt`: пять зависимостей без закрепления версий.
- `cache/*.json`: девять локальных файлов с домами и конкурентами.
- `README.md`: только название проекта; инструкции запуска и публикации отсутствуют.

## Что проверено исполнением

Проверки выполнялись через Flask test client и небольшие диагностические сценарии. Для расчётов использованы существующие файлы кэша, а для отказов — контролируемые подстановки. Реальные сетевые запросы к Overpass в этих сценариях не выполнялись.

Главная страница возвращает HTTP 200. Все шесть сочетаний районов и типов бизнеса возвращают HTTP 200, 3600 оценок с конечными значениями в диапазоне 0–1 и источник `cache`. Первый расчёт занял около 596 мс, последующие — 39–81 мс в этой среде; загрузка из сети сюда не входит.

## Проблемы по приоритету

### 1. Передача и публикация проекта

В локальном `HEAD` находятся только `.gitignore` и `README.md`. `app.py` и `static/index.html` добавлены в индекс как пустые файлы, их содержимое находится в незакоммиченных изменениях. `osm.py`, `requirements.txt`, `check.py` и кэш не отслеживаются. Поэтому текущая рабочая версия ещё не представлена полноценным локальным коммитом для передачи другим.

Состояние удалённой ветки независимо не подтверждено: веб-инструмент не получил страницу репозитория, запрос GitHub API из терминала завершился запретом доступа к сокету. Эти ошибки не доказывают, что репозиторий отсутствует или закрыт.

В `app.py:222` сервер запускается на `127.0.0.1:5001` с `debug=True`. Такой запуск доступен на самом компьютере. Настроек публичного развёртывания, производственного сервера и проверки готовности приложения нет.

GitHub Pages размещает статические HTML/CSS/JS-файлы и сам по себе не исполняет Flask API: [документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Для текущей архитектуры нужен Python-хостинг. Для публикации Flask предписывает отдельный WSGI-сервер: [документация Flask](https://flask.palletsprojects.com/en/stable/deploying/).

### 2. Неполные исходные данные

В Университетском кэш содержит 17 домов по три жителя каждый. Приложение выдаёт предупреждение, но продолжает показывать «лучшую точку». Для содержательной рекомендации сначала нужно проверить координаты области, исходные теги OSM и полноту выборки жилых зданий.

`osm.py:172` загружает только контуры типа `way`; здания типа `relation` не учитываются. Для `building=yes` большой дом без этажности и количества квартир отбрасывается. Исполнением подтверждено: здание площадью 500 м² с адресом и без этажности даёт `None`, маленькое площадью 100 м² — три жителя. Это показывает механизм пропусков, но не доказывает, что именно он объясняет всю выборку Университетского.

Жители оцениваются по площади, этажности или квартирам, а не берутся из переписи. Категория `cafe` дополнительно включает магазины кофе, выпечки и кондитерские. Дедупликация конкурентов по округлённым координатам способна объединить разные организации рядом. Требуются проверка выборки и документирование допущений.

### 3. Карта зависит от внешней загрузки

Leaflet JS/CSS загружаются с `unpkg.com`, подложка — с `tile.openstreetmap.org`. Кэш домов и конкурентов не сохраняет библиотеку и подложку карты. Поэтому утверждение в комментарии `osm.py` о работе без интернета относится лишь к части данных.

При выполнении текущего JavaScript без загруженного Leaflet возникает `ReferenceError: L is not defined` до регистрации обработчиков кнопок. Этот сценарий воспроизведён в изолированном JavaScript-окружении; фактический отказ CDN у пользователя не подтверждён. Обработчиков ошибок загрузки библиотеки и тайлов и резервного источника подложки нет.

OSM предоставляет тайлы без гарантии доступности и рекомендует возможность смены источника. Для автономной карты нужен источник, допускающий такой режим: [правила OSM](https://operations.osmfoundation.org/policies/tiles/).

### 4. Загрузка не ограничена одной минутой

`osm.py:67` последовательно обращается к двум серверам. Для HTTP 429/504 предусмотрены повторные попытки. Контролируемая имитация HTTP 504 показала четыре запроса и две паузы по пять секунд для одной загрузки. Таймаут запроса — `(10, 60)`; дома и конкуренты загружаются последовательно. Общего ограничения времени операции нет, поэтому обещание интерфейса «до минуты» не обеспечено.

В `static/index.html:273` у `fetch` нет отмены или прикладного таймаута. Пока запрос выполняется, пользователь может менять район и тип бизнеса. В сценарии смены Елецкого на Центр до прихода ответа интерфейс отобразил результат Елецкого при выбранном Центре.

### 5. Кэш скрывает часть проблем обновления

Повреждённый свежий JSON вызывает `JSONDecodeError`, загрузчик сети не вызывается: воспроизведено через реальную функцию `_cached` с подставленным файловым интерфейсом. Для готового района ошибка может привести к демо-данным, для произвольной области — к ошибке API.

При `refresh=True` и отказе загрузчика функция успешно возвращает старый файл с признаком `cached=True`. Интерфейс не получает причину сбоя и дату исходных данных. Устаревшая копия полезна, но пользователь должен видеть, что обновление не удалось.

Запись файла выполняется непосредственно через `write_text`, без атомарной замены и координации одновременных запросов. Это риск повреждения или дублирования загрузок при публикации; конкурентный сбой отдельно не воспроизводился. Ключ кэша не содержит версию модели оценки населения.

### 6. Расчёт выходит за границы выбранной области

Дома отбираются внутри круга, а сетка кандидатов строится в квадрате без круговой маски (`app.py:167`). На синтетических данных все пять домов находились внутри радиуса 1000 м, но API рекомендовал точку примерно в 1343 м от центра. Ошибка воспроизведена через реальный API.

Дополнительно кандидаты не фильтруются по воде, дорогам, паркам, доступным участкам и помещениям. Расстояния прямые, а не по пешеходным маршрутам. Поэтому вывод «математически идеальное место для открытия» нужно ограничить условиями модели.

### 7. Центроиды не определяют рекомендуемую точку

Взвешенный K-means корректно используется для расчёта центров скоплений в метрах. Однако `km.cluster_centers_` служат только для отображения; оптимальная точка выбирается независимым максимумом `спрос / (1 + alpha × конкуренция)` по сетке.

Нужно явно описать эту двухчастную модель в проекте либо сделать центроиды основой генерации кандидатов. Оценка нормируется на максимум каждой области: 90% означает долю от лучшего результата текущего расчёта, а не вероятность успеха и не сопоставимый между районами балл.

### 8. Дополнительные ошибки API

Запрос с допустимыми координатами и `radius=nan` возвращает HTTP 500 из-за `int(NaN)` вместо ошибки ввода HTTP 400. Неизвестные район и тип бизнеса молча заменяются значениями по умолчанию. Внутренние ошибки возвращаются пользователю с техническими подробностями.

## Порядок доработки

1. Сформировать полный воспроизводимый состав проекта, README и версии зависимостей. Проверить запуск из чистой копии.
2. Проверить географию областей и качество данных, особенно Университетского. Подготовить проверенные исходные наборы для демонстрации и порог достаточности данных.
3. Устранить ошибки инициализации карты, добавить понятные состояния загрузки и ошибок, защиту от устаревших ответов и ограничение времени.
4. Исправить круговую границу расчёта, проверку числовых параметров и обработку кэша. Сохранять дату, происхождение и версию данных; явно сообщать о неудачном обновлении.
5. Уточнить роль центроидов и смысл рейтинга. Добавить географические ограничения для пригодных мест.
6. Подготовить Python-хостинг с WSGI, HTTPS, постоянным хранилищем кэша, проверкой готовности и контролем затратных запросов. Затем проверить сайт из другой сети и на телефоне.

Для небольшого учебного проекта можно сохранить Flask и Leaflet. Проверенные данные готовых районов целесообразно обновлять заранее, а произвольные области загружать с ограничениями. Это уменьшит зависимость обычного пользовательского расчёта от Overpass.

## Границы анализа

Код приложения и исходный кэш не исправлялись. Полноценная визуальная проверка в браузере, актуальная доступность Overpass/CDN/тайлов из сети пользователя, состояние удалённого репозитория и развёртывание на публичном хостинге не подтверждены. Успешные расчёты из кэша не доказывают работоспособность всей цепочки внешней загрузки.
