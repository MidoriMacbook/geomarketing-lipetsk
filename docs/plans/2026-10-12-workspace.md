# Рабочее пространство: план реализации

**Цель:** согласованный редизайн и функциональный набор для пяти типов бизнеса.
**Спецификация:** docs/specs/2026-10-12-workspace-design.md.
**Архитектура:** каталог Python, совместимый Flask API, Leaflet и браузерные
сохранения. Без новых runtime-зависимостей и платных сервисов.
**Глобальные ограничения:** сохранять прежний API `best` и обработку отказов;
максимум 3 рекомендации, 250 м разделения, 12 сохранений, 3 места в сравнении;
не сравнивать относительную оценку между расчётами; не выдавать отсутствие данных
о конкуренции за успешный пустой результат.

## Задачи

- [x] 1. Backend: failing tests в tests/test_workspace.py на каталог и рекомендации;
  запустить `.venv/Scripts/python.exe -m unittest discover -s tests -p test_workspace.py -v`.
  Затем создать businesses.py и расширить app.py. `/api/catalog` и добавленные поля
  отвечают контракту спецификации. `best` сохраняет прежние координаты.
- [x] 2. Геоданные (параллельно после определения каталога): osm.py использует теги
  из businesses.py; отдельные снимки grocery/bakery/beauty для каждого района.
  scripts/import_osm_competitors.py импортирует разовую OSM XML-выгрузку и сохраняет
  ту же форму JSON. Проверить теги и корректный отказ без снимка.
- [x] 3. Frontend: сначала сценарий tests/browser-workspace.js, подтвердить отсутствие
  новых элементов на старом UI. Затем static/index.html, static/workspace.css,
  static/workspace.js: новый экран, 5 категорий, карточки, слои, localStorage,
  сравнение, CSV, печать. Каталог загружается через `/api/catalog`, рекомендации
  через прежний `/api/calculate` с дополнительными полями из спецификации.
- [x] 4. Интеграция: полный unittest, браузерные сценарии, desktop/mobile screenshots;
  поправить регрессии старой проверки без удаления её смысла. Проверить отказ
  CDN, тайлов, API, storage и устаревшие ответы.
- [x] 5. Ревью: независимая проверка correctness/security, исправить существенные
  замечания с регрессионными тестами. Обновить README и data/README.md.
- [ ] 6. Публикация: коммит, fast-forward main, GitHub Actions, ручной deploy
  существующего `srv-db65pi8473hc73d7s5vg`; дождаться live и проверить публичный
  `/healthz`, 15 сочетаний район/бизнес и браузер. Платные ресурсы не создавать.

## Файлы и ответственность

Backend: businesses.py, app.py, tests/test_workspace.py.
Геоданные: osm.py, scripts/import_osm_competitors.py, data/snapshots/, data/README.md.
UI: static/index.html, static/workspace.css, static/workspace.js,
tests/browser-workspace.js. Backend и UI согласуют только JSON-контракт выше.

## Особые случаи ревью

Ни одного конкурента; менее трёх полезных точек; повреждённая запись localStorage;
блокировка browser storage; сравнение разных категорий; смена района в процессе
загрузки; нехватка данных новой категории; экспорт CSV с пользовательскими строками.
