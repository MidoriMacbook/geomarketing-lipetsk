# Ежедневная доставка данных — итоги 25 октября 2026

[Спецификация](../specs/2026-10-25-data-delivery-proposal.md) описывает получение проверенной городской выгрузки через GitHub Actions. Два запроса Overpass выполняются ежедневно; постоянная ветка данных `osm-data` хранит `city.json` отдельно от кода и перезапусков Render.

`scripts/collect_city_data.py` и `.github/workflows/osm-data.yml` публикуют данные атомарно, ограничивают конкурирующие запуски и сохраняют прежнюю версию при отказе. `src/domain/city_data.py` проверяет схему, полноту и фильтрацию; `src/services/city_feed_service.py` загружает версию с сохранением исходной даты. Поле `data_delivery` добавлено в ответ анализа без изменения модели и архивов.

Кнопка «Проверить обновления» различает новую, прежнюю и недоступную версию; интерфейс показывает периодичность и дату. Сохранённые исследования продолжают использовать собственный снимок.

Историческая проверка включала повреждение файла, откат даты, пустые категории, конкурентные запросы, отсутствие сети/файла, начальную загрузку, район/категорию/свою область и мобильный экран. Выполнялись Python/Node, проверка структуры, реальный запуск GitHub Actions и загрузка с Render; повторная проверка той же версии не меняла `fetched_at`.

Существующих Python/requests/numpy достаточно; новых платных ресурсов и аккаунтов нет. Сборка зависит от периодической доступности Overpass, загрузка — от GitHub HTTPS. Результаты: [проверка ежедневной доставки](../verification/2026-10-25-daily-city-data.md).
