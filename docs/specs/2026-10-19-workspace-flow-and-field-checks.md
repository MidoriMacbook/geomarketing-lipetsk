# Рабочая зона и проверка места на месте

Статус: реализация по подробному заданию пользователя от19октября2026.
Исходное задание: attachment a9ee739c-a4dd-4a0c-a4bd-8a6921451c11/Вставленный текст.txt.
Пользователь уже определил композицию, взаимодействия, checklist и приёмку;
дополнительного согласования того же дизайна не требуется.

## Аудит и направление

Это аналитическая рабочая панель с сохранением существующего оформления,
а не новый лендинг. Material Web, Golos/Unbounded, сливовые/розовые поверхности,
серо-синие дома/ягодные конкуренты и motion/counters сохраняются.
Причина пустоты: .workspace align-items:start и фиксированная высота #map;
высокие рекомендации не растягивают центральную карточку. Подробная data-section
между workspace и сохранениями усиливает разрыв.

## Композиция

- От1024px карта и рекомендации образуют общий растягиваемый ряд. От1280px
  настройки — левая колонка;1024–1279 допустима компактная строка настроек над
  парой карта/рекомендации. При768px две колонки или последовательный поток,
  при390px порядок settings → map → recommendations.
- map-card — flex/grid column; #map растёт через доступное пространство.
  Минимум карты нужен при0/1рекомендации, комфортный предел рабочей зоны
  около48–76rem, адаптивно к viewport/масштабу текста. При превышении ограничивается
  список рекомендаций с доступной вертикальной прокруткой, а не контент карточек.
  В desktop map-card не ниже recommendations; декоративных наполнителей нет.
- ResizeObserver контейнера карты вызывает invalidateSize с RAF/защитой от
  повторов, без пересчёта модели и скачка выбранной точки. Window resize fallback
  сохраняется; слои и позиции выбранного места не сбрасываются от disclosure.
- Порядок после workspace: сохранённые места/сравнение, исследования при наличии,
  данные и ограничения, footer. Все прежниеid/testid/ARIA сохраняются.

## Данные и объяснения

- В заголовке карты компактный #trust-status/#trust-summary и ссылка
  #trust-details-link href=#data-section. Начальное состояние не выдаёт старые
  данные за новые; во время refresh прежний результат подписан явно.
- #data-section находится непосредственно перед footer. Заголовок «Данные и
  ограничения расчёта», короткое резюме и закрытый #data-details с источником,
  датами домов/конкурентов, свежестью, учётом/ограничениями модели и проверками
  перед арендой; #source/#data-quality/#data-warning/#refresh-data сохранены.
- «Проверить детали» открывает нижний disclosure, прокручивает к нему с учётом
  reduced-motion и даёт понятную точку фокуса. Предупреждения компактны по умолчанию.
- «Почему это место» содержит спрос относительно текущего расчёта, жителей/радиус,
  конкуренцию/ближайшего конкурента, фактические strengths/risks/field_checks и
  ограничение модели. Данные берутся из существующего проверенного explanation,
  без новых обещаний прибыли или вымышленных сравнений.
- Печать содержит подробности/объяснения открытыми в отдельном печатном DOM;
  состояние раскрытия экранных карточек не влияет на полноту отчёта.

## Исследования

Полные сценарии уже реализованы. Их не удаляем и не откладываем заново.
Видимые названия заменяются на «Исследования», storage/ids/API-free restore прежние.
Крупный раздел и ссылка навигации скрыты при отсутствии исследований; ошибка
чтения/неизвестная версия открывает recovery UI, а не делает данные недоступными.
Небольшое действие #scenario-save остаётся доступным после результата вне скрытого
раздела, чтобы первое исследование можно было создать. Сам раздел появляется после
сохранения либо при наличии старых записей. Контекст не смешивается с saved places.

## Микровзаимодействия

- Desktop hover невыбранной карточки: lift3–6px, тональная тень/граница и preview
  её маркера. Выбранная карточка не прыгает; touch не зависит от hover.
- Selection: спокойное выделение/короткий marker pulse и существующий мягкий pan;
  соседние карточки читаемы, действия доступны. Hover не меняет selectedRank/ARIA.
- Native details + общий initDisclosure(details) поддерживают Enter/Space, видимый
  фокус, быстрые повторные открытия, динамический контент и reduced-motion.
  Раскрытие использует grid/clip/WAAPI с конечным доступным состоянием; фокус не теряется.
- Панели появляются один раз в viewport, смещение8–16px/задержки0–90ms.
  Повторный расчёт анимирует результат; переключение слоя не повторяет entrance.
- Кнопки получают hover/press/saved feedback; disabled читаемы. Нет постоянных
  pulse/glow, parallax/scroll-jacking и новых библиотек. Reduced-motion убирает
  движение немедленно, включая уже активные эффекты; сохранённый count-up не ломается.

## Пользовательская проверка

Только у сохранённого места: закрытый «Проверить на месте» с подписью
«Проверка пользователя», прогрессом и7фиксированными bool-пунктами из задания:
помещение, вход, парковка/остановка, поток людей, ручная проверка конкурентов,
аренда в бюджете, фото/заметки добавлены отдельно. Фото/заметки здесь не загружаются.
Чек-лист не влияет на score/API и не модифицирует saved.v1/scenarios.v1.

Отдельный ключ geomarketing.field-checks.v1:
`{schema_version:1, records:[{place_id, checks:[bool×7], updated_at:ISO}]}`.
place_id — точный id существующего сохранённого места. Строгое чтение и ограничения
размера64k/48записей, bool×7, уникальныеid<=160символов, корректные даты.
Обновление latest-read внутри отдельного Web Lock; изменения других мест/вкладок
не теряются. При отсутствии locks чтение доступно, изменение отключено.
Ошибки доступа/quota/повреждение/неизвестная версия не переписывают key и не
ломают карту; UI откатывает несохранённую отметку и сообщает результат.
Удаление места убирает только его checklist после успешного удаления места;
автоматического массового удаления/миграции нет. Recovery при повреждении может
очистить только этот key после отдельного явного подтверждения и exact-raw проверки.
Storage event обновляет отметки без потери фокуса; нормальный saved/CSV/print контракт прежний.

## Интерфейсы между задачами

- HTML: trust-status/trust-summary/trust-details-link, data-details и data-summary;
  существующиеsource/data-quality/data-warning/refresh-data и сценарныеid на месте.
- ui.js export initDisclosure(details, options={}) — безопасен при повторном вызове.
- map.js export hoverPlace(rank, active) — визуальный preview без изменения выбора.
- field-checks.js export fieldChecksBlock(placeId) -> HTMLElement,
  removeFieldChecks(placeId) -> Promise; инициализация локальна saved-card.
- field-check-storage.js — чистый модуль без DOM/чтения browser globals при import;
  readFieldChecks, setFieldCheck, deleteFieldChecks с инъекцией storage/locks для Node.
- CSS нового checklist: отдельный field-checks.css, подключаемый в HTML.
