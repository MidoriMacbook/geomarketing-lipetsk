# Этап A · Мои поправки

Ветка `feature/niche-finder`, исходная версия интерфейса `40f3186`. Этап 0 принят; его отчёт опубликован отдельным коммитом `ac033a6`. Этапы B–F не входят в эту реализацию.

## Совместимость

Обычный GET `/api/calculate` остаётся прежним: те же поля и сериализация, та же единственная функция `score_locations`, те же формула, нормирование и отбор. POST без поля `corrections` вызывает тот же путь. Проверка побайтовой совместимости фиксирует UUID, часы и источник данных: текущий API уже генерирует новый `analysis_id` и `calculated_at` при каждом вызове, поэтому два независимых живых ответа сейчас не равны побайтно.

До изменения кода фиксируются эталоны Центр × кофейня и Елецкий × кофейня на неизменяемых входных снимках. Проверяются байты ответа при фиксированных часах/UUID и отдельно координаты, порядок рекомендаций, баллы, сетка. Нулевые поправки и сброс возвращают исходные численные результаты.

## Серверный контракт

POST на существующий маршрут принимает JSON с прежними параметрами области/категории и необязательным объектом `corrections: {added: [{id, lat, lng}], removed: ["node:123", "way:456"]}`. Идентификатор OSM включает тип объекта: числовые ID узла и контура могут совпадать. Ручные ID имеют собственное пространство имён.

Явно переданный пустой объект поправок включает расширенный ответ режима редактирования: устойчивые идентификаторы исходных конкурентов, источник каждого объекта, сводку поправок и исходное сравнение. Отсутствие параметра сохраняет старый ответ без дополнительных полей. В обычном режиме идентификаторы не добавляются в прежний JSON.

Идентичности проходят рядом с массивом координат от уже имеющегося provenance до расчёта. Они не выводятся по порядковому номеру и не угадываются по совпавшим координатам. Для старых данных без OSM ID удаление недоступно до обновления исходного набора; интерфейс объясняет причину. Демонстрационные записи не выдаются за OSM.

Валидация: суммарно не более 50 активных добавлений и удалений, конечные координаты, допустимая область, уникальные ручные ID, отсутствие повторов удаления. Удалять можно только ID исходного набора соответствующей области и категории. Ошибочные ID и превышение лимита возвращают понятную ошибку, а не частично применённый расчёт. Размер JSON ограничен. Общий кэш исходных данных не меняется; массивы для поправок создаются отдельно для запроса.

Исходный и изменённый наборы проходят через одну реализацию формулы и отбора. Результат исходного расчёта переиспользуется в пределах версии данных и параметров. Кэш поправок ограничен по размеру и ключуется версией исходных данных, областью, категорией и каноническим набором поправок. Цель измерения на прогретом кэше — не более 2 с; результат публикуется как измерение, а не гарантия сети.

## Сравнение баллов

После изменения конкуренции новый вариант может оказаться в другом месте. Дельта считается для координат нового места относительно исходной поверхности оценки в той же позиции сетки. Нельзя вычитать баллы двух разных мест лишь потому, что оба были «Место 1». Дополнительно отмечается появление нового места. Пояснение у дельты: относительный балл внутри расчёта; поправки могут изменить нормирование. Исходный максимум не превращается в фиксированную денежную или вероятностную шкалу.

## Мобильный режим

Отдельная кнопка «Мои поправки» включает явный режим с действиями «Добавить конкурента», «Убрать конкурента», «Отменить», «Сбросить», «Готово». Пока он включён, проверка произвольной точки не перехватывает тап. В режиме добавления короткий тап на пустом участке карты создаёт ручной маркер. В режиме удаления тап по OSM-конкуренту открывает подтверждение с отменой. Перетаскивание и pinch остаются жестами карты. Удаление собственной ручной метки отменяет добавление, а не создаёт фиктивное удаление OSM.

История отмены хранит предыдущие наборы поправок. Сброс можно отменить последним действием. При превышении 50 поправок состояние не меняется и показывается предупреждение. Смена области/категории не переносит поправки в другой расчёт; несохранённые поправки явно подтверждаются перед сбросом. Исходные и применённые поправки различаются в состоянии клиента.

Debounce 500 мс; версия запроса и AbortController не позволяют старому ответу заменить новый. Во время пересчёта используется skeleton результатов, карта сохраняет центр и масштаб. При ошибке остаются последние успешные места, отображаются неприменённые поправки и действие повторного расчёта. Карточки и слои обновляются плавно, reduced-motion отключает перемещения. Ручной конкурент отличается значком и подписью «добавлен вручную».

Постоянное пояснение: «Поправки меняют только ваш расчёт и хранятся в браузере; данные OpenStreetMap не изменяются».

## Исследования и экспорт

Контейнер исследований получает schema_version 2. Чтение версии 1 сохраняет названия, заметки, идентификаторы, даты, снимок расчёта и вид карты; отсутствие поправок интерпретируется как пустой набор. Обновление записи происходит транзакционно после успешной проверки, без очистки старого ключа до успешного сохранения. Ошибка quota/валидации оставляет старую запись целой. Снимок версии 2 содержит применённые поправки и происхождение конкурентов; неподтверждённый неудачным пересчётом набор не подменяет сохранённый результат.

В исследовании, на карте и в отчёте показываются счётчики «добавлено вручную: 2, убрано: 1». В CSV конкурентов добавляется колонка «источник»: OSM / вручную. Показатели сохранённых мест и их существующие CSV-поля сохраняются; ручные конкуренты не смешиваются с вручную выбранными местами.

Печатаемый чек-лист включает выбранное место, оценку, ближайших конкурентов и расстояния, сведения о поправках, поля заметок и отметки «подтверждено / нет». Адрес используется только если известен; иначе печатается «Адрес: __________________» и координаты, без выдуманного геокодирования. PDF создаётся штатной печатью браузера, без внешнего сервиса.

## Риски и проверки

1. Потеря соответствия ID и координат при фильтрации. Регрессии для node/way с одинаковым числовым ID, дублей координат и старого источника без ID; удаление неизвестного ID запрещено.
2. Устаревший ответ после отмены/сброса. Проверки отложенных ответов, серии быстрых действий, ошибки пересчёта и смены категории. Общий источник данных никогда не мутирует.
3. Потеря старых исследований. Фикстуры схемы 1, миграция без изменения содержимого, отказ записи localStorage, повторное открытие схемы 2 и восстановление поправок.

Unit: полная совместимость без параметров, добавление/удаление/сброс/отмена, лимит, некорректные входы, единственная формула, дельта в одной позиции, происхождение CSV. Playwright Chromium/WebKit: весь мобильный путь, независимость режима от проверки точки, панорамирование, сохранение и восстановление, старые исследования, печатный чек-лист. Подлинный pinch на физическом iPhone остаётся ручной приёмкой; эмуляция не выдаётся за устройство.

Снимки до/после: 375×667, 390×844 и 1440 px — вход в режим, добавление, подтверждение удаления, изменённые рекомендации, восстановленное исследование и чек-лист. Отчёт публикует результаты unit, обоих движков, времени расчёта, ссылки на изменённые файлы и честные ограничения. После этапа A работа останавливается.
