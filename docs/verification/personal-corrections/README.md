# Этап A. Мои поправки

Ветка `feature/niche-finder`. [Согласованная спецификация](../../specs/2026-11-18-personal-corrections-design.md) · [Исследование категорий этапа 0](../../research/categories.md).

На карте можно добавить отсутствующего конкурента, убрать метку из расчёта, отменить действие или сбросить набор. Лимит составляет 50 поправок. Если несколько объектов OSM стоят в одних координатах, диалог предлагает выбрать конкретный объект по типу и ID. Для данных без ID доступно добавление. Удаление ручной метки отменяет её добавление.

Запрос отправляется через 500 мс после последнего действия. Пока сервер пересчитывает места, видны статус и компактный скелетон. Центр и масштаб карты сохраняются. Если запрос завершился ошибкой, черновик остаётся на карте, а карточки показывают последний успешный результат. Успешное обновление показывает разницу с исходным баллом в тех же координатах.

Исследование сохраняет только применённые поправки и открывает их без запроса геоданных. Схема 2 читает старые снимки схемы 1. В браузере можно выгрузить CSV конкурентов с источником и распечатать чек-лист выбранного места. Если адрес неизвестен, в нём остаётся поле для заполнения и указаны координаты.

## Совместимость расчёта

В эталонном тесте часы, UUID и источник зафиксированы. Обычный GET совпал с исходным ответом на Windows, а POST без поля поправок совпал с GET. Отдельно сравниваются сетка, координаты, порядок и оценки.

| Область · категория | Мест до и после | Баллы до и после |
| --- | ---: | --- |
| Центр · Кофейня | 1 | 100 |
| Елецкий · Кофейня | 2 | 100 и 26 |

## Проверки браузера

Прошли 166 тестов Python и 114 тестов JavaScript. В WebKit прошли все 70 smoke-сценариев. В Chromium прошли 68 сценариев до последних уточнений режима, затем 10 целевых сценариев поправок и мобильных параметров на итоговом коде. Чек-лист проверен в печатном PDF на одной странице A4.

Playwright проверяет добавление и два вида удаления, выбор среди совпавших меток, отмену, сброс, отложенные ответы, повтор после ошибки и открытие архивов обеих схем. В Chromium используется нативный ввод CDP для панорамирования и щипка. В WebKit проверены касания и панорамирование доверенными указателями. Щипок на физическом iPhone остаётся ручной проверкой.
