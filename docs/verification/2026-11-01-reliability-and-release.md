# Надёжность данных и пользовательских сценариев

Проверка от 1 ноября 2026 года. База изменений — `5cfdded`. Палитра, шрифты,
численная формула, ключи хранилищ и чтение старых архивов сохранены.

## Исправления и границы совместимости

Ошибка `pobeda/cafe` без CITY_DATA_URL, сети и кэша воспроизведена как HTTP 500
до исправления. Fallback теперь проверяет конкретную пару район/категория.
Из 100 пар шесть имеют демонстрационные примеры, остальные 94 возвращают
понятный HTTP 400 при полном отсутствии данных. Своя область не получает demo.
Маркировка примера сохраняется в интерфейсе, сохранениях, CSV и печати.

Новые данные содержат параллельные метаданные происхождения: OSM type/id,
настоящую дату получения, теги и признаки оценки населения. Повтор одного ID
удаляется; противоречивый повтор отклоняется. Разные близкие ID сохраняются.
Пары точки/контура и совпадающая геометрия отмечаются как неопределённость.
Старые numeric rows и city schema:1 читаются; расширение необязательно.
Полные записи остаются в источнике/кэше, API передаёт компактную сводку,
совместимую с ограничением размера браузерных исследований.
Реальный результат с происхождением сохранён в браузере: архив 31 161 символ,
153 идентифицированных дома; ошибок JavaScript нет.

Исправлены также два повреждённых входа кэша: boolean вместо населения и
некорректная слишком большая дата. Они не должны скрывать пригодный снимок.
Импорт конкурентов требует `--fetched-at`; mtime больше не выдаётся за дату источника.

«100 из 100» явно означает относительный балл только внутри одного расчёта.
Рекомендации, сохранения, сравнение, CSV и печать используют общую подпись;
хранимые числа остаются 0…1, CSV экспортирует подписанную шкалу 0…100.
Даты локализованы, технические ISO скрыты из основных пояснений. Основное
ограничение OSM доступно без вложенного раскрытия. Повтор warning/notice,
найденный на независимом ревью, воспроизведён отдельным браузерным тестом
до исправления; после него предупреждение показывается один раз.

На телефоне название, балл и подпись рекомендации разделены на строки,
общая стрелка сохраняет собственное место. Новый редизайн не проводился.

В расширенной матрице плитки подменены локальным PNG; отказы API, тайлов,
хранилища, Clipboard и внешних переходов задаются явно. Физическая печать
и системный буфер обмена не проверяются: проверяются DOM отчёта и переданные значения.

локальных конкурентов. Адаптированы тесты/контролируемая среда; production-багами
эти наблюдения не объявляются. После изменений workspace, scenarios,
scenarios-ui и legacy-enrichment прошли без pageErrors.

## Команды, CI и ревью

- `python -m unittest discover -s tests -p 'test_*.py'`: 134/134.
- `node --test tests/unit/*.test.js`: 92/92.
- Новый автономный `pnpm run test:smoke`: 4/4, локальный Chromium.
- `python scripts/validate_project.py`: 92 обязательных файла, DAG/imports,
  DOM id, палитра и локальные assets — успешно.
- Hero: воспроизводимая сборка 315 624 байта / 104 243 gzip, upstream-хеши сохранены.
- Material Web пересобран после перевода собственных комментариев; повторная
  сборка проверяется на совпадение. Код сторонних компонентов не менялся.
- `git diff --check` и скан незавершённых заглушек — без найденных проблем.

CI использует закреплённый Playwright 1.64.1, один worker, без retries;
Python requests к сети запрещён, внешние браузерные запросы блокируются.
При отказе сохраняются trace/screenshot/JSON. Полная историческая матрица
не запускается при каждом коммите; push osm-data не запускает основной CI.

Независимое backend-ревью дополнительно выполнило 72 целевых теста и проверило
реальный bundle/семь SHA ответов. Frontend-ревью проверило шкалу, архивы,
отчёты и CI; найденный повтор предупреждения исправлен регрессией.
Переводы комментариев проверены сравнением AST/содержимого без комментариев;
лицензии и исходники сторонних компонентов сохранены.

Удалены только доказанно неиспользуемые save-line и старый print-селектор
kpi-progress. Служебные журналы исключены из Git с сохранением локальных файлов;
решения перенесены в текущую архитектуру/README. Исторические отчёты не выдаются
за сведения о текущем размещении. Локальные доказательства находятся в
игнорируемом `tests/artifacts/2026-11-01`.

## История и публикация

Подготовка истории выполняется отдельно от обычной публикации кода.
[Порядок, leases и восстановление](../maintenance/git-history-cleanup-plan.md).
Проверенная репетиция snapshot-04 содержит 126 коммитов, 56 refs, 0 тегов;
все деревья, авторы/коммитеры, даты и порядок родителей сохранены.
Восстановление bundle и fsck проверены независимо. Все 16 веток codex/*
не содержат уникальной работы относительно main, но их удаление/перенос
не выполняется без согласования. Восемь подписанных коммитов сохраняют байты
подписей; после изменения сообщений/родителей подписи недействительны.

После обычного commit/push нужен свежий снимок с последним main/osm-data,
новой копией, таблицей SHA и точными leases. Перед force требуется решение
владельца о подписях и именах веток, приостановка старых запусков data workflow
и повторная проверка heads. Подготовительный скрипт не выполняет remote mutations.
Внешние клоны, reflog, PR refs и кэши не входят в гарантируемую область очистки.

Обычный push main уже разрешён владельцем; Render autoDeploy использует ту же
ветку. Фактический commit/status CI и Render проверяются после отправки, затем
содержимое публичных assets сравнивается с Git. Локальный smoke сам по себе
не доказывает публикацию. Для этой проверки отдельный формальный коммит не нужен.
