# Восстановление обновления OSM — 25 октября 2026

## Причины и исправления

- Прежний HTTP read timeout10s не покрывал очередь Overpass. Диагностический GET вернул корректный JSON за28.3s, полноценные дома с gall — за34.9s. Query timeout увеличен8→25s, HTTP read до40s, два набора используют общий бюджет повторов85s. Браузер ожидает100s и предупреждает о полутора минутах.
- Узел lambert за общим адресом отвечал502/timeout; gall вернул253исходныхобъекта домов. Использован официальный отдельный узел gall как временный обход сбоя, резерв Private.coffee сохранён. User-Agent содержит ссылку проекта. GET проверен на реальных выборках.
- `out center tags` не гарантирует lat/lon у node. Запрос конкурентов изменён на `out body center`, сохраняющий координаты точек и центры ways/relations.
- Ответ с remark отклоняется целиком, чтобы частичная выборка не становилась свежим пустым списком конкурентов. HTTP502/503/504, вернувшийся быстрее3s, допускает один повтор при достаточном бюджете;429 и timeout немедленно на том же узле не повторяются.
- Ошибка сети записывает hostname, тип ошибки и HTTP-статус без URL с координатами. Кэш/снимки, значения дат и модель не подделываются; сохранённая копия при отказе источника остаётся с прежней датой.

## Источники решения

Документация оператора допускает отдельный официальный узел при неисправности другого и описывает очередь до15s: https://dev.overpass-api.de/overpass-doc/en/preface/commons.html
Форматы `tags`, `body`, `center`: https://dev.overpass-api.de/overpass-doc/en/targets/formats.html
