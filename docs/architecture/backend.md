# Серверные модули

## Ответственность и разрешённые импорты

| Модуль | Назначение | Может использовать |
| --- | --- | --- |
| `src/config.py` | Корень проекта, CACHE_DIR, SNAPSHOT_DIR, server_host/server_port, ограничения и параметры | Стандартную библиотеку |
| `src/routes/health.py` | `/healthz` | Flask |
| `src/routes/catalog.py` | `/api/catalog`, JSON | Flask, catalog_service |
| `src/routes/calculate.py` | `/api/calculate`, семафор2, ошибки, параметры | Flask, analysis_service, validation |
| `src/domain/businesses.py` | Десять категорий, R, alpha, OSM-теги | Константы |
| `src/domain/models.py` | Данные области и результатов загрузки/вычислений | Типы и dataclasses |
| `src/domain/scoring.py` | Взвешенный K-means, спрос, конкуренция, сетка, рекомендации | NumPy, SciPy, sklearn, geo, config |

| `src/services/catalog_service.py` | Каталог районов и категорий | config, businesses |
| `src/services/cache_service.py` | Проверка JSON, атомарная запись, stale, блокировки | Файлы, время, models, config |

HTTP-логика не выполняет кластеризацию и не пишет файлы. Вычисления не
читают request.args, не возвращают jsonify и не делают сетевых запросов.
Сервисы возвращают обычные данные; routes определяют HTTP-статус.

## Результаты, которые необходимо сохранить

Дома — `[lat,lng,residents]`, конкуренты — `[lat,lng]`.
Кэш и исходные снимки читаются как старые массивы либо объект
`{fetched_at,data}` с дополнительными полями происхождения.
CacheInfo сохраняет cached/fetched_at/stale/warning и bool-семантику.
Успешный пустой список конкурентов отличается от ошибки загрузки.
Для новых категорий нет выдуманных демонстрационных конкурентов.

18октября добавлены `calculated_at`, `analysis_context` и `data_quality`, а также
`explanation` у рекомендаций и `best`. Сервис обогащает уже рассчитанные точки;
scoring и прежние числа неизменны. Функции domain не знают о Flask/HTML/сети.
Свежесть определяется старейшей известной датой домов/конкурентов:24часа/7дней,
missing/future — unknown, demo не получает реальную свежесть. Полнота — признаки
пригодности модели и причины, а не процент покрытия. Нулевые отмеченные конкуренты
не означают отсутствие бизнеса. Риск на краю использует круг, которым loader
фильтрует дома, включая диагональные точки; запас конкурентов рассматривается отдельно.
Подробный контракт и пороги: docs/specs/2026-10-18-scenarios-and-explainability.md.
Серверные маршруты сценариев не добавляются: снимки принадлежат браузеру.

Ближайший конкурент может находиться за границей круга анализа: запас выборки
равен max(400м,R). Ключи категорий с R>400 включают _haloR:
например pharmacy_halo500, beauty_halo450 и fitness_halo900.
Снимки и пользовательский кэш остаются в прежнем формате и под прежними именами.

## Риски переноса

Пути вычисляются от корня проекта, а не от положения нового сервисного файла.
В Docker необходимо копировать `src/`. Тесты с mock должны подменять функцию
там, где она вызывается; исправляются адреса подстановок, а не ожидаемые результаты.
Вложенные тесты требуют `__init__.py`, чтобы unittest discover не пропустил их.

## Обновление OSM — 25 октября 2026

**Новая схема Render:** при `CITY_DATA_URL` анализ использует `city_feed_service`.
`city_data` проверяет городской контракт и фильтрует круг домов/прямоугольник
конкурентов с прежним halo и дедупликацией. Сборщик GitHub использует общие
`parse_houses`/`parse_competitors`, сохраняя модель населения. Городская рамка
покрывает все разрешённые центры и максимальный радиус/halo.
`LoadedData.delivery` необязателен; payload добавляет `data_delivery` только
для daily-режима. CacheInfo, старые API-ответы и архивы не изменены.
При отказе daily берутся только сохранённые снимки, без Overpass.
Даты не меняются при проверке той же версии или отказе. Подробности: DEPLOYMENT.md.

Overpass GET использует `out body center` для конкурентов, чтобы nodes сохраняли координаты. Источники: основной overpass-api.de, независимый глобальный узел VK Maps и Private.coffee. Отдельный gall удалён: он воспроизводил отказ основного узла с Render и не давал независимого резерва. Query timeout 25s, read timeout до 40s. `loading_budget` через ContextVar ограничивает повторные попытки двух загрузок общим окном 85s; бюджет не протекает между запросами Waitress. При исчерпании бюджета загрузка прекращается сразу. Быстрый 502/503/504 повторяется один раз при оставшихся >45s; timeout/429 не повторяются на том же узле. Remark означает неполный ответ и не попадает в кэш. Браузер ждёт 100s. Форматы API/CacheInfo/снимков и модель не изменены.
