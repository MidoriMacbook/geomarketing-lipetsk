# Спецификация архитектуры и редизайна

Пользовательский промт от12октября2026 является согласованным заданием.
Сохранить стек и функциональность, распределить модули по ответственности,
описать значимые изменения и проверить результат. Переписывание с нуля исключено.

## Визуальное решение

Urban-tech / editorial analytics. Тёплый почти белый фон, глубокий хвойный
зелёный, один лаймовый акцент. Система поверхностей: фон страницы,
тонированная панель управления, светлое полотно карты, выделенная первая
рекомендация, отдельный сохранённый рабочий список. Радиусы небольшие,
тени слабые и функциональные. Главный заголовок выразительнее текущего,
числа tabular, подписи читаемые, длинные строки ограничены по ширине.

Токены определяются в `static/css/tokens.css`, включая карту: цвета, радиусы,
тени, типографика, интервалы, размеры и z-index. JS читает семантические CSS-цвета.
Состояния hover/focus/active/pressed/loading/empty/error/selected/saved явные;
цвет не является единственным признаком. Минимальный целевой размер действия44px.

## Композиция

Header объясняет продукт и текущий раздел. Intro объясняет результат анализа.
KPI показывают текущий расчёт. Desktop: компактные настройки, доминирующая карта,
компактные рекомендации. Первое место выделяется даже до выбора;
выбранная карточка и маркер имеют один номер. Сохранить — основное действие.
Номер, score, жители, конкуренты и ближайший конкурент быстро читаются.
Уведомления расположены рядом с соответствующим блоком, не перекрывают карту.

Mobile: заголовок→KPI→настройки→карта→рекомендации→сохранённые→сравнение.
Достаточная высота карты; таблица сравнения прокручивается только внутри контейнера.
Проверка ширин360,390,768,1024,1280,1440px, keyboard и reduced-motion.

## Обязательная совместимость

Сохранить район, пользовательскую область, радиус, тип бизнеса, расчёт, KPI,
карту/слои, рекомендации, сохранение, сравнение, CSV, печатный отчёт,
объяснение модели и состояния. Не менять API-маршруты, JSON-форматы,
схему localStorage, data-testid, id и aria-связи. Прежние записи восстанавливаются.
Пять категорий и пятнадцать сочетаний с готовыми районами должны работать.

## Структура и проверки

Целевая структура описана в docs/architecture/*.md. В корне допускаются
тонкие совместимые osm.py/businesses.py для существующих импортов и py_compile.
Внутренняя реализация находится в src. check.py переносится в scripts.
Тесты распределяются по unit/integration/browser с сохранением утверждений;
дополняются проверкой контрактов, чистого пути импорта и адаптивности.
Docker/README/CI используют новую структуру. CHANGELOG обновляется по этапам.

Проверки: полный unittest discover, py_compile корневых входов и src,
node --check всех восьми JS-модулей, scripts/validate_project.py,
два браузерных сценария, шесть ширин, ошибки API/тайлов/Leaflet/storage,
две вкладки, print CSS, CSV, отсутствие циклов и заглушек.
После проверки — независимое ревью и обновление существующего бесплатного Render.
