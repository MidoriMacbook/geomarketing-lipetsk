# Подготовка переименования истории Git

Операция подготовлена только в отдельной локальной копии. Исходные `main`, рабочие файлы и удалённые ссылки не переписываются. После обычного финального коммита проекта снимок истории необходимо обновить.

## Правило сообщений

Русский язык, строчные буквы, 2–5 слов, без точки, префиксов `feat/fix/docs/chore` и служебных пометок: «резервный режим», «проверка дублей», «мобильные отступы». Те же правила применены ко всем старым сообщениям, включая длинные русские и автоматические коммиты `osm-data`.

## Воспроизводимая подготовка

Из корня репозитория, с новой, ещё не существующей папкой:

```powershell
.venv/Scripts/python.exe scripts/prepare_history.py --output .maintenance/history-2026-11-01/final-snapshot --refresh-remote --retain-invalid-signatures-for-rehearsal
```

Флаг разрешает исключительно локальную пробу с побайтным сохранением прежних подписей и явной отметкой их недействительности. Без него скрипт останавливается на первом подписанном коммите после создания копии. Используются установленные Python и Git. Сетевая операция читает удалённые головы и теги в изолированное зеркало; исходные `origin/*` не передвигаются. Папка должна быть новой и находиться внутри `.maintenance`; рекурсивные удаления не нужны. Неизвестное некорректное сообщение останавливает пробу; для него есть `--titles путь.json`: полный старый SHA → название.

Результат:

- `refs.json`: исходные и удалённые SHA, рабочие копии, время и SHA-256 копии;
- `before.bundle`: все исходные refs, включая локальные, `origin/*`, внутренние ссылки приложения и актуальный `osm-data`;
- `restore-check.git`: независимое восстановление из bundle;
- `rehearsal.git`: зеркало с пробно переименованными сообщениями;
- `messages.md`, `mapping.json`: старый SHA → старое сообщение → новое сообщение → новый SHA для всех достижимых коммитов;
- `rewritten-refs.json`: все пробные ссылки, включая забытые;
- `branches.json`: уникальные относительно `main` коммиты и нейтральные имена;
- `signatures.json`: подписи со статусом `invalidated_by_message_change`;
- `verification.json`: проверки деревьев, заголовков, топологии и исходных refs;
- `lease-commands.ps1`: точные команды с сохранением прежних имён веток;
- `rename-lease-commands.ps1`: альтернативный атомарный перенос `codex/*` в `archive/*` с удалением прежних имён;
- `rollback-commands.ps1`: обратные leases для варианта прежних имён.

Команды представлены для рассмотрения, а не запуска. Перенос имён — альтернатива: его нельзя выполнять после первой операции без нового снимка. Фактические результаты и полный список сообщений находятся в локальном `tests/artifacts/2026-11-01/history-report.md`. Копии не публикуются.

## Проверка сохранности

`git bundle verify`, полный список bundle refs и независимое восстановление подтверждают наличие всех исходных ссылок в копии. Восстановленная копия и пробное зеркало проходят `git fsck --full --no-reflogs`.

Объекты читаются и записываются побайтно через `cat-file` и `hash-object`. Для каждого коммита сравниваются `tree` и все заголовки, кроме значений `parent`: автор, коммитер, даты, дополнительные поля, подпись. У родителей сохраняются количество, порядок и соответствие SHA по mapping. Каждый новый объект перечитывается и сверяется с ожидаемыми байтами. Удаление служебных журналов допускается только новым обычным коммитом: содержимое старых деревьев не меняется.

Все пространства refs рассматриваются явно: оставленная ветка или `origin/*` со старым SHA сохраняет старую историю. Внутренние ссылки приложения на деревья сохраняются как деревья и не являются дополнительной историей коммитов. Рабочие копии и внутренние commit refs нужно согласовать перед реальным локальным переключением. Одного сброса `main` недостаточно.

## Подписи и граница готовности

Обнаружены подписанный начальный коммит и подписанные ежедневные коммиты. Изменение сообщения или родителя меняет объект: прежняя подпись больше не подтверждает новый коммит. В пробе байты `gpgsig` сохранены ради строгой проверки метаданных; валидность подписи не утверждается.

Публикация заблокирована до отдельного решения владельца: сохранить недействительные исторические подписи с пояснением либо разрешить их удаление или создание новых подписей уполномоченными ключами. Последние два варианта выходят за пределы изменения только сообщений и требуют новой пробы. Скрипт не подделывает, не удаляет и не создаёт подписи. Подписанный аннотированный тег останавливает подготовку. В текущем снимке тегов нет.

## Ветки и рабочие копии

В текущем снимке одна рабочая копия на `main`. Все 16 локальных и удалённых `codex/*` входят в `main`; уникальных коммитов нет. Локальная и удалённая головы `harmonious-map-mobile-spacing` различаются, но обе включены в `main`. Это не разрешение удалять ветки: могут существовать чужие рабочие копии. Поиск PR через подключённый GitHub не нашёл записей; это не доказывает отсутствия внешних ссылок.

В `branches.json` предложены `archive/schetchiki`, `archive/arhitektura` и другие нейтральные имена. Перенос сохраняет каждый проверенный tip; пустой lease на новое имя запрещает перезапись существующей ветки. Удаление прежних имён требует отдельного подтверждения владельца. Если при обновлении снимка появятся уникальные коммиты, их нельзя отбрасывать: перенести переписанный tip и согласовать продолжение работы с владельцем.

## Пауза ежедневной публикации

`osm-data` унаследовала общую историю приложения от коммита сборщика, затем добавила ежедневные данные. Переписывать только `main` недостаточно.

Владелец отдельно разрешает приостановку `.github/workflows/osm-data.yml`, отмену выполняющихся и ожидающих запусков и запрет ручного запуска на время изменения ссылок. Примеры после такого разрешения:

```powershell
gh workflow disable osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
gh run list --workflow osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
# Для каждого активного запуска после проверки номера:
# gh run cancel НОМЕР --repo MidoriMacbook/geomarketing-lipetsk
```

Запуски используют `GITHUB_SHA` начала работы: старый запуск может вернуть старую историю через создание `osm-data` от прежнего `main`. После паузы и отмены нужен новый финальный снимок refs и bundle, затем проверка leases. Не удалять и не переинициализировать `osm-data` из старого `main`: новый проверенный tip уже сохраняет тот же `city.json`. Если данные изменились во время подготовки, lease должен отказать; затем повторить пробу.

До возобновления заменить сообщение в `scripts/publish_city_data.py` на «ежедневные данные города» обычным коммитом, иначе старый формат появится снова. Включить workflow на новом `main` и начать новый запуск:

```powershell
gh workflow enable osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
gh workflow run osm-data.yml --ref main --repo MidoriMacbook/geomarketing-lipetsk
```

Проверить, что родитель первого нового data-коммита — переписанный tip `osm-data`, сообщение короткое и русское, содержимое прошло валидацию. Старые запуски не перезапускать. В текущем этапе workflow не отключался.

## Публикация и восстановление

Перед публикацией владелец должен увидеть свежий диапазон всех 126 либо большего числа коммитов, все refs, старые и новые SHA, путь и SHA-256 bundle, проверки и ограничение подписей. Публикация, пауза workflow и удаление веток не выполнены и требуют отдельного подтверждения.

Команды выполняются из `rehearsal.git` с явно заданной переменной `$historyRemote` публичного репозитория. У каждой обновляемой или удаляемой ссылки есть `--force-with-lease=полная-ссылка:старый-SHA`; у новой — lease с ожидаемым отсутствием. `--atomic` сохраняет согласованный набор. Отказы leases, защиты веток или atomic нельзя обходить ослаблением условий.

Для восстановления создать новую папку из `before.bundle`, сверить SHA-256 и все `refs.json`; не удалять текущую копию. Для прежних имён подготовлены обратные команды с lease на новый SHA. Для переноса имён восстанавливать старые имена из bundle только с leases на отсутствие, а `archive/*` удалять с leases на конкретные новые SHA и отдельным разрешением. Новую работу после операции сначала сохранить, а не стирать.

После согласования локально обработать все `heads`, теги, `origin/*`, worktrees и внутренние commit refs по mapping. Незакоммиченная работа сохраняется отдельно; bundle её не содержит. Автоматического разрушительного переключения текущей папки нет.

Область очистки — сообщения достижимых коммитов и согласованные имена контролируемых refs. Старые SHA могут остаться в bundle, reflog, обсуждениях, PR refs, кэшах, чужих клонах и внешних ссылках; исчезновение не гарантируется. Лицензии, авторство, зависимости, Material Web, React Bits и файлы старых деревьев сохраняются.
