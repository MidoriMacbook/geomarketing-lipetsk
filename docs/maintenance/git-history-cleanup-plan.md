# Обслуживание опубликованной истории Git

## Текущее правило

Старые сообщения коммитов остаются в опубликованной истории. Очистка файлов
проекта не меняет уже выпущенные версии, их SHA, теги и ссылки проверок.
Все новые сообщения коммитов пишутся по-русски и описывают действие для проекта,
например: «Уточнить статусы показателей карты» или «Очистить документацию проекта».

## Возможная отдельная операция

Переписывание старых сообщений изменяет SHA и затрагивает все зависимые коммиты.
Для такой операции необходимы резервная копия репозитория, перечень затронутых
ссылок, согласование принудительной публикации изменённой истории и координация
с владельцами рабочих копий. После неё потребуется обновить ссылки на SHA,
сведения о выпусках, проверки и инструкции синхронизации.

Эта операция не выполняется в текущем этапе. Команды разрушительного изменения
истории здесь не приводятся; обычная публикация продолжает дополнять main.

## Границы аудита файлов

Проверяются отслеживаемые README, CHANGELOG, DEPLOYMENT, docs, scripts, static,
src, tests и конфигурация. Исключены Git-метаданные, установленные зависимости,
локальные результаты проверок, lock-файлы и код сторонних библиотек с лицензиями.
Запись `.codex` в `.dockerignore` остаётся техническим исключением локальной
папки из Docker-контекста; сама папка в репозиторий не добавляется.

Имя стандартного HTTP-заголовка `User-Agent` необходимо для обращений к публичным
сервисам. Оно сохраняется в конфигурации и технических сведениях о запросах.
GitHub Actions, Render, OpenStreetMap, Leaflet, Material Web, React Bits,
названия публичных API, лицензии и действующие ссылки не заменяются.
