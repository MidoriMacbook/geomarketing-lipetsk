# Подготовка переименования истории Git

Текущий выбранный вариант — удалить старые криптографические подписи из
переписанных коммитов, сохранив подписанные оригиналы в проверенном bundle.
Разрешены подготовка и локальная проверка; force-push требует отдельного
подтверждения владельца для конкретного свежего пакета.

## Одна актуальная операция

Указатель `.maintenance/history-2026-11-01/current-operation.json` называет
единственную актуальную папку. Реальные числа, heads и SHA-256 копии берутся
из её refs.json/signatures.json/verification.json. Владелец согласовывает
operation.md, mapping и точные команды. Старые команды не исполняются.

| Репетиция | Состояние при создании | Назначение |
|---|---|---|
| snapshot-04 | 126 коммитов, 8 подписанных | Историческая, с недействительными подписями |
| final-snapshot | 129 коммитов, 10 подписанных | Последняя прежняя репетиция; команды не исполнять |
| Папка из current-operation.json | Вычислено заново | Единственный вариант для нового согласования |

Существующие папки и копии не перезаписываются. При изменении heads/tags,
рабочих копий или кода нужна новая папка, проверка и обновление указателя.

## Подготовка

Обычный коммит кода/workflow/документов и его push выполняются до снимка.
Нужно дождаться нового daily-run. Затем из корня, в ещё не существующую папку:

```powershell
.venv/Scripts/python.exe scripts/prepare_history.py --output .maintenance/history-2026-11-01/unsigned-final --refresh-remote --strip-signatures
```

Чтение удалённых heads/tags выполняется в отдельное зеркало. Исходные main,
origin/*, рабочие файлы и удалённые ссылки не меняются. Изменение heads во время
снимка останавливает подготовку. Для повторения нужна новая папка.

Сообщения — короткие, по-русски, строчными буквами, 2–5 слов, без точки и
префикса; описывают содержание исходного коммита. Неизвестное некорректное
сообщение останавливает пробу; дополнение передаётся через --titles JSON
(полный исходный SHA → название). Порядок и число коммитов сохраняются.
Сообщение scripts/publish_city_data.py уже исправлено в c28ba37 на
«ежедневные данные города»; заново менять его не требуется.

## Подписи и инварианты

Парсер читает целое поле Git со всеми продолжениями. Удаляются только
явно разрешённые gpgsig/gpgsig-sha256. signatures.json перечисляет исходный/
новый SHA, удалённые поля и хеши их байтов; оригиналы остаются в bundle.
Никто не подписывается чужим именем. Временный SSH-ключ изолированного теста
принадлежит только тестовой личности и не публикуется.

mergetag — встроенный тег со своей семантикой, а не обычная подпись коммита.
Без отдельного правила его наличие останавливает подготовку. Подписанные
аннотированные теги также требуют отдельного решения. Неизвестные заголовки
и их продолжения сохраняются побайтно.

Допустимы только согласованные сообщения, mapped parent SHA и перечисленные
удаления полей подписи. Для каждого коммита проверяются неизменность дерева,
авторов/коммитеров/дат и прочих заголовков, число и порядок родителей.
Обязательны git bundle verify, все bundle refs, независимое восстановление
и fsck восстановленной/переписанной копий. Изолированный тест использует
настоящий SSH-подписанный коммит и merge с несколькими родителями.

## Пакет операции

- before.bundle и restore-check.git — исходные объекты/refs и независимое восстановление.
- refs.json — исходные/удалённые/зеркальные refs, время, worktrees и хеш копии.
- messages.md и mapping.json — все старые/новые SHA и сообщения.
- signatures.json — фактически удалённые поля; исходные подписи в bundle.
- rewritten-refs.json, branches.json, verification.json — целевые refs, уникальная работа и инварианты.
- operation.md — один конкретный диапазон и порядок исполнения для владельца.
- rename-lease-commands.ps1 и rename-rollback-commands.ps1 — точные прямые и
  обратные atomic-команды для main/osm-data и переноса 16 codex/* в archive/*.

Различающиеся локальный и удалённый tips учитываются отдельно. Нельзя заменять
локальный tip удалённым без проверки уникальной работы. Новые archive-имена
защищены ожидаемым отсутствием. Уникальная работа не удаляется; auxiliary refs
тоже учитываются, чтобы забытая управляемая ссылка не оставляла старую историю.

## Исполнение только после подтверждения

1. Сначала определить состояние после любого прерывания: main/osm-data,
   старые codex/* и новые archive/*. Смешанное/неизвестное состояние требует
   остановки и разбора. Слепое повторение публикации или отката недопустимо.
2. Приостановить osm-data.yml и новые ручные запуски на время операции.
   Дождаться либо отменить ВСЕ старые running/queued/waiting runs, включая
   ручные. Это ещё не выполнялось. При наличии GitHub CLI:

   ```powershell
   gh workflow disable osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
   gh run list --workflow osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
   ```

   Отмена — только по проверенному ID нужного run. Старый run не должен
   опубликовать city.json с родителем из прежней истории.
3. Повторно считать все heads/tags и worktrees, сверить с актуальным пакетом.
   Любое расхождение означает отказ, новую копию/mapping/leases и согласование.
4. Сверить SHA-256 bundle и восстановление. Из rehearsal.git исполнить только
   утверждённую команду с --atomic и точными --force-with-lease. Публичный URL
   задаётся в $historyRemote, credentials в файлы не пишутся. При отказе atomic,
   leases или защиты веток остановиться; условия не ослаблять. Альтернативную
   команду с прежними именами не выполнять следом.
5. Сверить все целевые удалённые SHA, отсутствие старых codex-имён и наличие
   archive tips. Деревья main/osm-data должны совпадать с исходными.
6. Сохранить незакоммиченную работу: bundle её не содержит. По mapping обновить
   каждую локальную ветку, origin/* и управляемую auxiliary ref с проверкой
   ожидаемого старого SHA. Worktrees обновлять по одному, предварительно
   проверяя branch/HEAD/чистоту. Не выполнять reset --hard/clean, не удалять
   старую папку; не терять отличающиеся локальные tips.
7. Включить workflow на новом main и начать НОВЫЙ run, не повторять старый:

   ```powershell
   gh workflow enable osm-data.yml --repo MidoriMacbook/geomarketing-lipetsk
   gh workflow run osm-data.yml --ref main --repo MidoriMacbook/geomarketing-lipetsk
   ```

8. Проверить первый новый data-коммит: родитель — новый osm-data tip,
   сообщение «ежедневные данные города», валидный city.json и настоящие даты.
   Проверить CI и фактические Render commit/assets/API. Push не доказывает размещение.

## Откат и границы

Только при однозначно подтверждённом новом состоянии восстановить heads из
before.bundle подготовленной обратной atomic-командой. Старые имена защищены
lease на отсутствие, archive — на точный новый SHA, main/osm-data — на новый
SHA. При появлении новой работы сначала сохранить её и согласовать новый план.
Любое расхождение исключает слепой rollback.

Область очистки — согласованные сообщения, поля подписи и имена управляемых refs.
Старые SHA сохраняются в bundle и могут остаться в reflog, PR refs, внешних
кэшах и чужих клонах. Их исчезновение не гарантируется. Лицензии и авторство
React Bits, Material Web и других зависимостей не затрагиваются.
