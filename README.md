# ГеоМаркетинг Липецк

Сайт помогает сравнить места для кофейни или аптеки: показывает жилые дома,
конкурентов, взвешенные центроиды спроса и рекомендуемую точку в выбранном круге.
Можно выбрать готовый район или центр и радиус на карте.

## Запуск

Нужен Python 3.14. Из корня проекта:

```bash
python -m venv .venv
# Windows PowerShell:
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe serve.py
# Linux/macOS:
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python serve.py
```

Откройте http://localhost:8080. `serve.py` запускает Waitress на `0.0.0.0`,
поэтому сервер может обслуживать других посетителей. `python app.py` — отдельный
локальный режим на http://127.0.0.1:5001, отладчик по умолчанию выключен.

## Размещение на хостинге

### Render: первый публичный запуск

В репозитории подготовлен `render.yaml` для бесплатного Web Service в регионе
Frankfurt: Python 3.14, Waitress, healthcheck `/healthz`. При создании Blueprint
из этого репозитория Render применяет настройки автоматически. Платный диск и
база данных для первого запуска не нужны: исходные снимки районов включены в код.
Новые копии кэша пишутся в `/tmp/geomarketing-cache` и теряются при перезапуске;
снимки из репозитория остаются доступными.

Создание через dashboard: откройте
[Deploy to Render](https://render.com/deploy?repo=https://github.com/MidoriMacbook/geomarketing-lipetsk),
подключите свой GitHub и подтвердите создание бесплатного сервиса. После завершения
сборки откройте **URL, который вернул Render**; заранее выбранное имя не гарантирует
конкретного адреса. Проверка: `/healthz` должен вернуть `{"status":"ok"}`,
а расчёты всех трёх районов — отобразить координаты и карту.

Изменения ветки `main` автоматически запускают новую сборку на Render.
GitHub Actions отдельно проверяет тесты; перед отправкой очередного изменения
выполните тесты локально и проверьте зелёный статус CI после публикации.
У бесплатного тарифа есть режим сна после 15 минут без запросов; пробуждение
занимает около минуты. Это подходит для первого доступа к учебному проекту;
условия и лимиты описаны в [документации Render](https://render.com/docs/free).

Первый сервис размещён по адресу
[geomarketing-lipetsk.onrender.com](https://geomarketing-lipetsk.onrender.com).
Настройки и порядок последующих обновлений: [DEPLOYMENT.md](DEPLOYMENT.md).

### Другой Python-хостинг или VPS

Нужен хостинг с Python либо Docker и входящими HTTP-запросами. GitHub Pages
не выполняет Python API этого проекта. Браузер и API обслуживаются одним сайтом:
в клиенте нет адресов localhost, ключи и CORS для запуска не нужны.

Для Python-хостинга:

1. Загрузите актуальные файлы проекта в GitHub и подключите репозиторий к хостингу.
2. Выберите Python 3.14; команда сборки: `pip install -r requirements.txt`.
3. Команда запуска: `python serve.py`.
4. Путь проверки работоспособности: `/healthz` (ожидается HTTP 200).
5. Включите HTTPS средствами хостинга. Для VPS настройте HTTPS reverse proxy
   перед Waitress; посетители должны открывать домен сайта.

Переменные окружения:

| Имя | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт, назначенный хостингом |
| `HOST` | `0.0.0.0` | Адрес прослушивания Waitress |
| `CACHE_DIR` | `cache/` рядом с кодом | Каталог с правом записи для обновлённых геоданных |
| `OMP_NUM_THREADS` / `OPENBLAS_NUM_THREADS` | `1` в serve.py | Потоки численных библиотек |

С Docker:

```bash
docker build -t geomarketing-lipetsk .
docker run --rm -p 8080:8080 geomarketing-lipetsk
```

Контейнер работает от непривилегированного пользователя и содержит healthcheck.
Постоянный том на `/app/cache` сохранит обновления при перезапуске; каталог должен
быть доступен пользователю контейнера для записи. Без тома готовые районы всё равно
работают по снимкам из `data/snapshots/`. Сборку Docker следует проверить на машине
с установленным Docker; в текущей среде проверен запуск Waitress на Windows.

Сейчас предусмотрен один экземпляр сервера: не более двух одновременных расчётов,
остальные получают HTTP 503 с предложением повторить запрос. При росте аудитории
потребуются общий кэш, очередь обновлений и ограничения запросов на reverse proxy.
За размером кэша произвольных областей нужно следить: автоматическая очистка
старых файлов пока не реализована. Папку `cache/` можно очищать при остановленном
сервере; встроенные снимки в `data/snapshots/` сохраняйте.

## Карта и геоданные

- Leaflet 1.9.4 хранится в `static/vendor/leaflet/` вместе с лицензией: внешний
  CDN не нужен для запуска интерфейса. Тайлы карты загружаются из OpenStreetMap;
  интернет для подложки необходим. При сбое показана кнопка повторной загрузки.
- Дома и конкуренты получаются сервером через Overpass API. Браузер не обращается
  к Overpass напрямую.
- Готовые районы имеют начальные снимки данных. Обычный запрос быстро читает
  сохранённую копию. «Обновить данные» запрашивает OSM; при ошибке сохраняется
  предыдущая пригодная копия, а интерфейс показывает предупреждение.
- Дата копии видна пользователю; после 7 дней выводится предупреждение.
  Автоматической фоновой синхронизации пока нет.
- Повреждённый кэш пропускается. Запись атомарная. Изменение координат или радиуса
  меняет ключ кэша. Ошибка записи не отменяет успешно полученные данные.
- Для выбранного на карте участка без сохранённой копии нужен доступный Overpass.
  Если данных недостаточно, сайт просит выбрать другое место. Демо-режим готовых
  районов всегда явно помечен; его нельзя принимать за реальные данные.

Источник геоданных — [OpenStreetMap, ODbL](https://www.openstreetmap.org/copyright).
Правила использования [тайлов](https://operations.osmfoundation.org/policies/tiles/)
и [публичных Overpass-серверов](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances)
нужно учитывать при росте посещаемости. Для коммерческой нагрузки нужен подходящий
поставщик карты и геоданных. Описание снимков: [data/README.md](data/README.md).

## Что означает результат

Количество жителей **оценочное**, по тегам числа квартир, площади и этажности
зданий OSM. Это не перепись населения. K-means с весами числа жителей находит
центры спроса. Рекомендуемая точка вычисляется отдельно на сетке 60×60:

`спрос = Σ жителей × exp(-(расстояние / R)²)`

`конкуренция = Σ exp(-(расстояние до конкурента / (0.8 × R))²)`

`оценка = спрос / (1 + alpha × конкуренция)`

Кандидаты за пределами выбранного круга исключены. Цвет нормирован относительно
лучшей точки **в этом расчёте**; 90% не означает вероятность успеха бизнеса.
Расстояние измеряется по прямой. Модель не учитывает дороги, доступность помещений,
аренду, доходы, поток людей и полноту OSM, поэтому результат — ориентир для
дальнейшей проверки места, а не гарантия доходности.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты выполняются без сети и проверяют ошибки параметров, границы поиска,
сохранность кэша, конкурентное обновление и работу готовых районов без сети.
GitHub Actions запускает их на Linux.

Браузерная проверка (установленный `playwright-cli`, запущенный сервер):

```bash
playwright-cli -s=geomarket open http://localhost:8080 --browser=chrome
playwright-cli -s=geomarket run-code --filename=tests/browser-smoke.js
playwright-cli -s=geomarket close
```

Сценарий проверяет расчёт, отказ CDN, смену района во время запроса,
отказ/повторную загрузку тайлов, ошибку API и мобильный экран.
Для проверки восстановления реальных тайлов нужен интернет.
