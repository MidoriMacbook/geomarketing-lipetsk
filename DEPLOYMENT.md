## Порядок публикации

После изменений выполните серверные, структурные и подходящие браузерные
проверки из README. Отправьте обычный новый коммит в main и проверьте GitHub
Actions и список развёртываний Render. Действующий сервис автоматически
реагирует на новые коммиты; не запускайте повторное развёртывание, если оно началось.

Если автоматического запуска нет, используйте в панели Render
**Manual Deploy → Deploy latest commit**. После статуса live проверьте
/healthz, карту, расчёт, источники и ресурсы приложения. При неудаче сначала
изучите логи; создавать новый сервис для исправления не требуется. Откат
выполняется к предыдущему успешному выпуску в той же панели.

Для коммита только с документацией допустим `[skip render]`, согласно
[документации Render](https://render.com/docs/deploys#skipping-an-auto-deploy).
Новые сообщения коммитов пишутся по-русски. Опубликованная история не меняется;
[правила обслуживания](docs/maintenance/git-history-cleanup-plan.md).

Конфигурация для повторного размещения через Blueprint находится в render.yaml.
Она задаёт HTTP-проверку /healthz. Действующий сервис создавался через API со
стандартной проверкой порта; HTTP-путь можно выбрать в Health Check Path.
Бесплатный сервис может приостанавливаться без посетителей, поэтому первое
открытие после простоя занимает время. Актуальные ограничения тарифа:
[Render Free](https://render.com/docs/free).

## Переменные окружения

HOST и PORT определяют адрес запуска. CACHE_DIR задаёт каталог временного кэша;
на Render используется `/tmp/geomarketing-cache`. Он теряется при перезапуске,
а исходные снимки десяти готовых областей остаются в Git.

CITY_DATA_URL включает режим ежедневной городской выгрузки:

```text
https://raw.githubusercontent.com/MidoriMacbook/geomarketing-lipetsk/osm-data/city.json
```

Переменная описана в render.yaml. Для существующего сервиса её обновляют
отдельно, сохраняя остальные значения окружения. Без CITY_DATA_URL остаётся
прежний локальный режим Overpass и районных снимков. Секреты не нужны для
чтения публичной выгрузки и не должны попадать в репозиторий.

## Ежедневная городская выгрузка

GitHub Actions из `.github/workflows/osm-data.yml` собирает данные примерно
в 06:23 по Москве (03:23UTC); запуск может задержаться. В Actions доступен и
ручной Run workflow. Данные публикуются в ветке osm-data как city.json,
не вызывая пересборку кода и Render. Расписание публичного репозитория может
отключаться GitHub после длительного отсутствия активности; состояние проверяйте в Actions.

Приложение проверяет схему, покрытие, категории, дату и контрольную сумму до
атомарного сохранения `CACHE_DIR/city-v1.json`. Новая копия с ошибкой, откатом
версии или численно непригодным населением не заменяет рабочую.
Обычный расчёт использует память. Проверка источника ограничена по времени;
кнопка «Проверить обновления» выполняет явную проверку новой версии.

Повторная версия илиHTTP304 не меняет исходный fetched_at. Проверяйте
`data_delivery.mode=daily`, version и даты. Результат unchanged означает,
что новой версии нет. При отказе остаётся сохранённая городская копия, затем
готовые районные снимки, без сетевого Overpass с Render. При отсутствии копий
возвращается понятная ошибка. Отказ сбора нельзя считать успешным обновлением.

## Локальный Overpass и Docker

Прежний режим сохраняется для локальной работы. Загрузка двух наборов имеет
бюджет повторов 85 s, браузер ждёт до 100 s. Основной узел overpass-api.de,
независимые резервы — VK Maps и Private.coffee. Успех проверяется по обоим
`data_meta.*.cached=false` и новым fetched_at; source=osm само по себе
не доказывает полной свежести. Локальный успех не подтверждает доступность с Render.

Dockerfile копирует корневые точки входа и src. Пути снимков вычисляются от
корня проекта; локальные служебные каталоги исключаются через .dockerignore.
Новые платные ресурсы для текущего приложения не требуются.
